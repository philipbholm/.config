# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

Personal dotfiles/config directory for a macOS development environment. Version-controlled configs for shell, editor, terminal, window manager, coding agents (Claude Code, Codex CLI, Cursor agent CLI), and development workflow scripts targeting a Docker-based monorepo (Ledidi medical platform).

## Repository Structure

- `zsh/.zshrc` — Zsh config (symlinked to `~/.zshrc`). Key custom functions: `notify` (run command with macOS notification on finish), `tdl`/`tdlm`/`tsl` (tmux IDE layouts), `eff` (fuzzy open file). Aliases: `n` (nvim), `g` (git), `d` (docker), `t` (tmux attach/create), `ff` (fuzzy find with preview). Tool inits for eza, zoxide, fzf, starship, mise.
- `agents/AGENTS.md` — Harness-neutral global writing and workflow rules. `~/.claude/CLAUDE.md` and `~/.codex/AGENTS.md` link to this file; the Cursor agent CLI has no global-rules file and does not load it.
- `claude/` — Claude Code config: settings (model, permissions, MCP servers, hook declarations), custom agents, `statusline-command.sh`, and `bin/` helpers. Skills no longer live here — they moved to the tool-neutral top-level `skills/` and `skills.work/` (see below). `claude/agents/` and `claude/agents.work/` are the profile-agnostic and work-only agent dirs, both currently empty (the three `ledidi-*` reviewers were removed along with the `code-review` skill that drove them). Hook *scripts* live in `dev/` (see `dev/claude-notify.sh`).
- `codex/` — Codex CLI config: `config.toml` (trusted projects, MCP servers) and `rules/default.rules` symlinked into `~/.codex/`. No skills dir of its own — Codex reads the shared skills from `~/.agents/skills` (see `skills/` below).
- `skills/` and `skills.work/` — the one shared skill set for all three agents, authored as plain `SKILL.md` files (the mattpocock/agentskills format). `skills/` is general and installed on both profiles: `explain-diff-html` plus the vendored mattpocock skills (tdd, diagnosing-bugs, code-review, research, resolving-merge-conflicts, codebase-design, domain-modeling, prototype, wizard, grilling, writing-for-agents). `skills.work/` is work-only: `review-pr`, `pr-findings`, `fix-pr-feedback`. The installer links each entry into both `~/.claude/skills` (Claude reads only this) and `~/.agents/skills` (Codex and Cursor both read this) — one source, two symlink targets. `fix-pr-feedback` is tool-agnostic (no Claude `Workflow`); there is no `Workflow`-driven skill anymore.
- `dev/` — Development helper scripts symlinked to `~/bin/`. Core scripts:
  - `dev.sh` — Dev stack manager (auto-detects main vs worktree, wraps docker compose with correct override files). `dev nuke` needs `--yes` whenever stdin is not a tty — which is every agent Bash call — and is in `permissions.ask`.
  - No verification wrapper lives here anymore: the monorepo's own `lefthook.yml` gates all six workspaces (services/registries, services/patient-bff, apps/registries-frontend, apps/patient-frontend, apps/shell, packages/components), so run the underlying commands directly — `npm run build-ts`, `npx vitest run`, `npx biome check` — from the workspace you changed.
  - `tunnel.sh` — Cloudflared tunnels for frontend + API
  - `setup-stack.sh` — Prepare a worktree for work: npm install for the three workspaces the stack needs, type generation, supergraph composition, then a `sync-context` run so the worktree has its context files. It starts no containers; Docker and ports come from `dev up`. `--all` (or named workspaces) also installs the rest of the workspaces lefthook gates — several GB per worktree, hence opt-in; it warns at the end about any gated workspace left without `node_modules`.
  - `lib/workspace.sh` — Sourced by the other scripts. Owns stack identity (slot files under `~/work/.dev-stacks`, workspace/slot Docker labels), the base ports, and `dev_apply_context_ports`, the single placeholder substitution both `dev.sh` and `sync-context.sh` call.
  - `wt-up.sh` — Create a named, harness-agnostic worktree under `<repo>/.worktrees/`, checking out an existing branch or creating a new one from an optional start point.
  - `wt-down.sh` — Tear down the worktree you are standing in: `dev nuke --yes` (running it is the confirmation), then — only once its containers are verifiably gone — remove the directory and re-sync context. Refuses on a dirty tree and never deletes the branch (unlike the retired `gwd`, which discarded uncommitted work). Run only **after the PR is merged**; agents never invoke it (nor `dev down`/`dev nuke`) on their own initiative.
  - `mcp-datadog.sh` — Datadog MCP launcher shared by all three agents; maps `DD_API_KEY`/`DD_APP_KEY` → `DATADOG_*` so no secret lands in a tracked config
  - `browser.sh` — Launch the Chromium that `chrome-devtools-mcp` attaches to on `:9222`: Google Chrome if installed (work), else Brave (personal), on a persistent dedicated `--user-data-dir` (Chrome/Brave 136+ refuse remote debugging on the real default profile, so sign in once and that debug profile persists). Core, since all three agents drive the browser through that MCP. Symlinked to `~/bin/browser`; re-running while it is up is a no-op.
  - `claude-notify.sh` — macOS notification hook for Claude Code (Stop + Notification events) plus an on/off switch. Wired via the `hooks` block in `claude/settings.json`. Toggle with `claude-notify on|off|toggle|status`; state in machine-local `~/.claude/notify.state` (missing = enabled). Suppresses false "idle/done" alerts while Claude is busy: drops events from subagent transcripts, the redundant `idle_prompt` notification, and Stop while `background_tasks` (subagents/teammates/shells) are still in flight — so "done" only fires when genuinely at rest. Posts via `terminal-notifier` (osascript floor); clicking the banner focuses Alacritty. `codex-notify.sh` (Codex, wired via `notify` in `config.toml`) and `cursor-notify.sh` (Cursor CLI, wired via the `stop` hook in `cursor-agent/hooks.json` → `~/.cursor/hooks.json`) are the equivalents, so all three post the same banners. (Claude and Codex used to post to Telegram — retired 2026-08 in favour of macOS notifications.)
- `dev/context/ledidi-monorepo/` — Agent context templates for the monorepo. `dev/sync-context.sh` copies `CLAUDE.local.md` and `AGENTS.md` into the main repo and every worktree, substituting the `{{*_PORT}}` placeholders from that worktree's slot (or replacing the whole port section when no stack is running). The two files are kept byte-identical apart from the H1, and `sync-context` aborts rather than spread a divergence; the main checkout gets its own port and teardown wording, since it owns slot 0 and `wt-down` refuses to run there. `docs/` is **not** copied — the templates link those by absolute path, so their port placeholders stay literal and must be substituted from the port table by whoever reads them. `docs/review-rules.md` is the odd one out: nothing in the templates links it, because it is the review corpus the `review-pr` and `pr-findings` skills load rather than something an agent working in the monorepo needs.
- `dev/feedback/` — PR review learnings (mine/ and other/), distilled into `SYNTHESIZED_LEARNINGS.md`, which `review-pr` and `pr-findings` load
- `dev/.env.local.example` — Key names for the ngrok/NHN values `dev.sh` sources from the gitignored `dev/.env.local`
- `aerospace/aerospace.toml` — AeroSpace tiling WM (alt-based keybinds, vim-style navigation)
- `alacritty/` — Terminal config (JetBrainsMono Nerd Font, light/dark themes via symlink, Left Option as Alt for tmux)
- `tmux/tmux.conf` — Omarchy-style config; prefix Ctrl-Space (+ Ctrl-B secondary). `prefix+z` kills the pane and `prefix+Z` kills the window, neither confirming, and there is no zoom binding — worth knowing before you send either. The bindings are documented once, in [GUIDE.md](/Users/philip/.config/GUIDE.md) § Tmux; read it there rather than restating them here. `tmux.conf` itself is the ground truth if the two ever disagree.
- `git/config` — SSH commit signing, separate work identity via includeIf for `~/work/`. Git verifies against the **generated** `~/.ssh/allowed_signers`: `git/allowed_signers` is the tracked base, and `install-work.sh` appends the work key from `~/.ssh/github_work.pub`, so no per-machine key is committed. Re-run the installer after restoring keys.
- `gh/config.yml` — GitHub CLI settings (`co` alias for `pr checkout`). `gh/hosts.yml` is machine-local auth state and gitignored.
- `cursor/` — Cursor **editor** (GUI) settings (`settings.json`, `keybindings.json`), symlinked from `~/Library/Application Support/Cursor/User/`
- `cursor-agent/` — Cursor **agent CLI** config (distinct from the GUI): `statusline.sh` and `hooks.json` symlink into `~/.cursor/` (`hooks.json` fires `dev/cursor-notify.sh` on the CLI `stop` event, for macOS banners); `mcp.json` is a symlink on personal and a generated merge on work (see Work agent config). `cli-config.json` is a sanitized copy (auth stripped, not symlinked — Cursor rewrites secrets into the live file). See `cursor-agent/README.md` for restore steps. Skills come from the shared `~/.agents/skills`; the CLI has no global-rules file, so it loads the personal writing rules only where a repo carries its own `AGENTS.md`.
- `karabiner/` — Caps Lock → Esc (tap) / Ctrl (hold); Cmd+Tab → Ctrl+Tab in Cursor
- `borders/bordersrc` — JankyBorders window highlight (auto light/dark)
- `nvim/` — LazyVim config (Space leader, Tokyo Night theme, vim-tmux-navigator). Custom options in `lua/config/options.lua`, plugins in `lua/plugins/`
- `install.sh` / `install-common.sh` / `install-work.sh` / `install-personal.sh` — Profile-based bootstrap. `./install.sh work|personal` dispatches to the matching entry script; both source `install-common.sh` (brew, core dirs, Node LTS via nvm, symlinks, launch agents, theme, cleanup, LazyVim bootstrap, verification) then layer profile-specific packages and links, calling `setup_macos_defaults` (Dock autohide + pinned apps, battery percentage, fast key repeat, Finder hidden files/extensions) after their own Brewfile bundle. Idempotent.
- `Brewfile` / `Brewfile.work` / `Brewfile.personal` — Core packages plus per-profile package sets. Work adds Ledidi/dev tooling (cloudflared, watchman, lefthook, opentofu, aws-vpn-client, Chrome, ngrok, Slack); personal adds ansible, hcloud, helm, k3d, opentofu, Brave + Tailscale.
- `switch-theme.sh` — Set macOS appearance + alacritty theme + borders to `light`/`dark` (arg, or local clock: light 07–18). Run on login and hourly by the `com.philip.theme-watcher` launch agent (`launchd/`) — hourly rather than just at the boundaries because launchd fires StartCalendarInterval in a stale timezone after a TZ change; the script exits early when nothing changed
- `GUIDE.md` — Quick-reference for tools, tmux/nvim shortcuts, shell aliases, layout functions
- `AGENTS.md` (repo root) — What Codex and Cursor load for *this* repo: structure, install/verify commands, shell conventions, Conventional Commit rules. It restates facts from this file, so a change here that invalidates one of them has to be mirrored there.

## Key Patterns

**Worktree workflow**: Worktrees live at `<repo>/.worktrees/<name>` and are shared by every agent harness. New branch → `wt-up <name> <branch> [start-point]`; existing branch → `wt-up <name> <branch>`. Continue from the path it prints, then run `setup-stack` — that is what writes the untracked `CLAUDE.local.md`/`AGENTS.md`, so a worktree that skips it has none of the project rules loaded. The Docker stack is **opt-in** and tiered by what the task needs: nothing for tsc/biome/frontend unit tests, `dev up postgres -d` for the backend suite (vitest's global setup builds `registries-test` itself), full `dev up` for E2E and browser work. `dev up` fills in the port table itself and `dev down` re-syncs rather than deleting the files, so no follow-up `sync-context` is needed. **Teardown waits until the PR is merged** — agents never run `dev down`, `dev nuke`, or `wt-down` on their own initiative, and a green suite is not a reason to stop the stack. Post-merge teardown is `wt-down`. Stack identity keys on the worktree *directory name*, not the branch, so switching branches inside a worktree keeps its stack and ports. Existing `.claude/worktrees/*` checkouts remain supported until they are removed normally, but no new worktrees go there.

**Review**: local working diffs go through the built-in `/code-review`. GitHub PRs go through two work-only skills that differ only in what they do with the result: `review-pr` posts inline comments, `pr-findings` posts nothing and reports the major findings in chat with a suggested comment for each, for when Philip reviews someone else's PR and writes the comments himself. Neither carries review rules of its own — the whole corpus (test, backend-integration-test, security/authorization, event-sourcing, code-style, frontend, logging, PR structure) lives in `dev/context/ledidi-monorepo/docs/review-rules.md`, so editing it changes both skills. Both load that by absolute path alongside `docs/{architecture,backend,code-style,testing}.md` and `dev/feedback/SYNTHESIZED_LEARNINGS.md`.

**Notification hook**: `dev/claude-notify.sh` handles Claude Code's Stop + Notification events (macOS notifications via `terminal-notifier`), wired via the `hooks` block in `claude/settings.json`. The zsh `notify()` helper sends macOS desktop notifications and prefers `alerter`, falling back to `terminal-notifier` (in the Brewfile — `alerter` is no longer distributed via Homebrew) and then `osascript`.

**Script access**: Dev scripts are invoked via symlinks in `~/bin/` (e.g., `dev`, `tunnel`) and have zsh tab completions defined in `.zshrc`.

**Multi-agent parity**: Claude Code, Codex, and Cursor agent CLI are kept as identical as each allows. All three run the same MCP servers — `chrome-devtools` (core, attaching to the browser `dev/browser.sh` starts on `:9222`) and `datadog` (work-only, via `dev/mcp-datadog.sh`) — and no plugins at all: capability comes from MCP servers plus the shared `SKILL.md` files, not from any tool's plugin manager. The browser is unified: Claude dropped the Claude-in-Chrome extension so all three attach `chrome-devtools-mcp` to the same debug browser (no more `--isolated` — with `--browserUrl` it was a no-op). Skills are one shared set (`skills/` + `skills.work/`) linked into `~/.claude/skills` for Claude and `~/.agents/skills` for Codex and Cursor. The global writing rules are the one thing that can't be fully shared: Claude loads them from `~/.claude/CLAUDE.md` and Codex from `~/.codex/AGENTS.md`, but the Cursor agent CLI has no global-rules file — it reads instructions only per-project, so it sees the personal rules only where a repo carries its own `AGENTS.md`.

**Work agent config**: The base `claude/settings.json`, `codex/config.toml`, and `cursor-agent/mcp.json` hold only shared content. Work-only bits (Datadog MCP, Claude's `permissions.defaultMode: "bypassPermissions"`, Codex `~/work` project-trusts) live in `*.work.*` overlay files and are merged into real (non-symlink) live files on work machines by `dev/sync-agent-configs.sh` (run by `install-work.sh`; re-run after editing a base/overlay on a work machine). On personal machines the base files stay symlinked. Model and reasoning-effort are deliberately kept out of the tracked configs (Claude's `model`/`effortLevel`, Codex's `model`/`model_reasoning_effort`): each tool writes the runtime choice into its own live config, so switching model or effort never churns git. Same idea for SSH: `ssh/config` is the personal base (github.com → `~/.ssh/github`) linked by `install-common.sh`; `ssh/config.work` (github.com → `~/.ssh/github_work`, plus bitbucket) replaces the symlink in `install-work.sh`. Skills and agents follow the same split, but via per-entry symlinks rather than an overlay merge: `link_entries` in `install-common.sh` links each entry of `skills/` into both `~/.claude/skills` and `~/.agents/skills` (and `claude/agents/` into `~/.claude/agents`), and `install-work.sh` re-runs it with `skills.work/` (and `claude/agents.work/`) added. It prunes its own previous links first, so a personal reinstall on a former work machine drops the work skills while leaving any machine-local ones alone. Work shell functions (`wt-down`/`dev`/`prisma`/`sync-context`) live in `zsh/.zshrc.work`, sourced by `.zshrc` only when `~/work` exists.

## When Editing These Configs

- Shell functions/aliases go in `zsh/.zshrc`. Secrets load from `zsh/.zsh_secrets` (gitignored).
- Skills go in `skills/` (both profiles) or `skills.work/` (work only), authored as plain `SKILL.md` files; agents go in `claude/agents/` or `claude/agents.work/`. Claude settings in `claude/settings.json`. After adding or removing a skill or agent, re-run the installer for the profile — `~/.claude/skills`, `~/.agents/skills`, and `~/.claude/agents` are real directories of per-entry symlinks, not links to the repo.
- How the model writes to Philip is set in `agents/AGENTS.md`, which loads in every repo and reaches subagents through each harness's global instruction filename. Do not add a second copy to the monorepo templates; a duplicate drifts.
- Dev scripts are all Bash — `#!/bin/bash` or `#!/usr/bin/env bash`; none use Zsh. Scripts must be executable.
- The `.gitignore` excludes: cagent, configstore, kanata, neofetch, rstudio, raycast, AWSVPNClient, tmp, node_modules, .zsh_secrets, .zcompdump, and `.env` / `.env.*` with `!.env*.example` — so env values go in a `.env.local` and only the `.example` is tracked. This remote is public.

## Shorthand Phrases

- **"update the context"** — Update `CLAUDE.local.md` and `AGENTS.md` under `dev/context/ledidi-monorepo/` (relative to this repo root), plus any files they reference.
